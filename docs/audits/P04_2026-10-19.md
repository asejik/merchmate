### A. App Lock review (new since 16 October)
Read `src/lib/appLock.ts` line by line. Good: PBKDF2-SHA256, 150,000 iterations, a fresh 16-byte salt per secret; constant-time comparison; recovery codes drawn with rejection sampling (no modulo bias), ~59 bits; PIN and recovery code share one failure counter, so the recovery code cannot be used to dodge the wait; neither is ever stored or logged in readable form; the stored config is validated and a damaged one fails open on purpose (documented, since anyone who can edit storage could delete the lock anyway); `changePin` and `resetPinWithRecovery` verify the current secret first and a reset invalidates the old recovery code; erase-this-device clears the lock, the drafts and the backup timestamp. Residual limits, all by design: a 4-8 digit PIN has little entropy against someone who can read the stored hash (finding 2 and the "not encryption" note).

### B. Drafts review
`loadDraft` validates the container shape and discards damaged or empty drafts; nothing from a draft is rendered as HTML; the draft never goes through any network path.

## Checked and fine (re-verified today)
- **Live headers** (`curl -I`, `/` and `/sw.js`): `content-security-policy` (script-src `'self' 'wasm-unsafe-eval'`, `frame-ancestors 'none'`, no other origins), `x-frame-options: DENY`, `x-content-type-options: nosniff`, HSTS with preload, `referrer-policy`, `permissions-policy`, `cross-origin-opener-policy`; the service worker is `must-revalidate`.
- **XSS sinks:** no `dangerouslySetInnerHTML`, `innerHTML`, `eval`, `new Function`, `document.write`, `window.open`, `postMessage` or `location` writes anywhere in `src/`. The only `href =` assignment is the download link in `share.ts` for a blob URL the app created.
- **Network:** no `fetch`, `XMLHttpRequest`, `WebSocket` or `sendBeacon` in `src/`; `connect-src 'self' data: blob:` would stop one anyway.
- **Secrets:** production build searched for key, token, JWT and PEM patterns: none; no sourcemaps are published (0 `.map` files); the git history since 16 October contains no credential patterns; nothing reads `import.meta.env`. `.env.example` names `SUPABASE_SECRET_KEY` for Phase 2: it must never get a `VITE_` prefix. **Secrets to rotate: none.**
- **Supply chain:** 722 lockfile entries, all from `registry.npmjs.org`, all with integrity hashes. The only package with an install script is `fsevents` (macOS file watching, expected). New since 16 October: `@playwright/test` and `@axe-core/playwright` (both established, dev only, not shipped).
- **Backup schema vs stored types:** compared field by field; every stored field is typed, dates are revived, logos must be embedded images.
- **Dev server:** `vite.config.ts` has no `server.host`, so `npm run dev` listens on localhost only.
